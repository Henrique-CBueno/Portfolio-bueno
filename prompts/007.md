  ❓ Q16 - Sua API: conta, linguagem e limites. Primeiro, um fato que só você sabe: sua conta do Instagram é Business ou Creator? Se for pessoal, precisa trocar, senão não tem API.

  Sobre "atualizado no segundo": a API não consegue ser mais rápida que as fontes. O Instagram permite cerca de 200 chamadas por hora (uma a cada 18 s) e a cota do YouTube aguenta uma leitura a cada ~9 s. Então sua API consulta as fontes a cada ~20–30 s e empurra pro site via SSE. O visitante vê o número mudar sem recarregar, que é o mais perto de "ao segundo" que existe.

  Em que linguagem e onde hospedar?
  - (a) Java + Spring Boot (Fly.io, Railway ou uma VPS): o seu conteúdo rodando de verdade, com virtual threads e um circuit breaker (Resilience4j) em volta das chamadas pro Instagram.
  - (b) Node, Go ou outra.

  ➡️ (a). Transformei o perfil em profissional e nao quero que o site rode em cima dos conteudos atuais, pois vou lancar muita coisa ainda

❓ Q17 - O que acontece quando a sua API cai?
- (a) O site é estático com os últimos números gravados no build, e a API só "acorda" os números via SSE. Se ela cair, os nós mostram "último valor · há X min".
- (b) O site depende da API pra mostrar qualquer número.

➡️ (a). O site nunca quebra, e a queda vira conteúdo (veja Q16).

❓ Q18 - O que move as cenas copiadas? Sem a timeline do Remotion, o "frame" precisa vir de algum lugar:
- (a) Scroll: rolar a seção avança a cena, com as falas do roteiro (roteiro.ts) aparecendo como legenda no estilo do vídeo. É o vídeo virando scrollytelling.
- (b) Passos: botão "próximo", uma frase do roteiro por vez.
- (c) Simulador: controles reais, como o circuit breaker do mock (escrito à mão por conceito).

➡️ (a) como padrão pra toda cena copiada, porque reaproveita o roteiro e a sincronia por frase quase de graça, e (c) só nos conceitos que pedem brincadeira (o circuit breaker já está pronto).
